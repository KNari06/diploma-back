Как было — ключевые проблемы

🔲 Слепые пятна в идентификации элементов

SVG-иконки, <mat-icon svgicon="">, <img alt="">, Angular <a title=""> — дропались при сборке label. LLM получал пустую строку и угадывал из общего контекста.

📐 Неверный расчёт modal coverage

Viewport вычислялся как bounding box всех видимых узлов. На длинных страницах (1280×8000px) modal 720px высотой = 9% покрытия → не признавался блокирующим → фоновые кнопки оставались в кандидатах.

📦 Весь snapshot шёл в LLM без фильтрации

100–300 кандидатов в одном LLM-запросе. Много токенов, низкое S/N ratio, медленный ответ, выше риск неверного выбора.

☠️ Отравленный кэш после реджекта

Fake-success guard отклонял клик, но LLM-кэш не чистился. Следующий retry брал тот же кешированный неверный ref снова и снова.

🪟 Паразитные оверлеи блокировали retry

Неудачный клик открывал CDK-overlay/dropdown. При следующей попытке оверлей перехватывал клик или сам оказывался в кандидатах. Ни закрытия, ни детекции не было.

📋 Нет структурированного лога фейлов

При финальном отказе шага — только текстовая строка ошибки. Нельзя было группировать по стратегии, смотреть историю попыток, строить аналитику "stuck steps".

🔤 Регрессия с нелатинскими скриптами

Candidate pruner v2 ранжировал по token overlap выше semantic match → казахские/кириллические элементы получали низкий ранг из-за script mismatch, даже при верном смысловом совпадении.

🔄 Дублирование кода buildStrategyLocator

Логика конвертации LocatorEntry → Playwright Locator дублировалась в executor и builder. Drift между ними приводил к ситуации "builder валидирует, executor не может выполнить".

Effective Label Cascade — универсальный экстрактор идентичности

Viewport — снапшот момента записи Низкий При scroll/resize между записью и replay viewport может не совпасть. Modal coverage ratio станет неверным. Edge case — fullscreen modal на мобильном viewport или responsive breakpoint смена.
FailureEvidence — overwrite, нет истории Низкий сейчас Single bundle per step — last failure wins. Для chronic flaky шага теряется история. При росте "stuck steps analytics" — потребуется history array с TTL или отдельная таблица.
Recorded Description — async, fail-open Низкий Таймаут 2500ms, при LLM outage — description = undefined. Resolver при replay деградирует к 2-канальному режиму (fingerprint + snapshot) без предупреждения. Стоит логировать miss rate.
Angular attrs — exact match без fuzzy Низкий routerLink/formControlName сравниваются точно. Реструктуризация маршрутов (SPA migration) = fingerprint mismatch → fallback на LLM. Это поведение желательно (drift детектируется), но нужно знать о нём.
Идеи для развития
Идея 01

Pruner confidence score → fast path

Если pruner возвращает confidence > 0.95 по единственному кандидату — пропустить основной LLM-вызов. Потенциально экономит 50–80% LLM-расходов на простых элементах.

Идея 02

Кэш инвалидация по URL-prefix

Сейчас кэш глобальный по ref. После SPA-навигации — одни рефы → другая DOM. Инвалидация по url-prefix + ref точнее и не требует полного сброса при переходах.

Идея 03

Overlay whitelist по роли

Tooltip (role="tooltip"), cookie-banner, autocomplete dropdown — их не надо закрывать при retry. Whitelist по aria-role / data-role предотвратит false dismissal.

Идея 04

FailureEvidence → WS real-time

Сейчас bundle сохраняется в БД, фронт не знает. Событие preview:step:failure-evidence позволит показывать inline-диагностику прямо в редакторе при фейле.

Идея 05

Pruner A/B режим (shadow)

Запускать pruner параллельно "в тени" рядом с полным кандидат-листом и сравнивать выборки. Если pruner срезал правильный кандидат — логировать precision miss без влияния на результат.

Идея 06

Recorded Description miss rate метрика

LLM timeout 2500ms + fail-open → тихий деградейд. Счётчик recordedDescription.misses в metrics позволит алертить при деградации LLM-сервиса до его влияния на replay точность.

Идея 07

locator-config.ts → UI настройки

346-строчный конфиг стратегий уже per-workspace. Следующий шаг — UI в настройках workspace где команда может приоритизировать стратегии без изменений кода (например, отключить vision для медленных CI).

Идея 08

Декларативный overlay whitelist

В locator-config.ts добавить parasiticOverlay.ignoreSelectors[] — список CSS-селекторов, которые никогда не закрываются автоматически. Позволит кастомизировать поведение под конкретные сайты.
