🔌 WebSocket Flow

Real-time connections, events, and updates for test progress and graph visualization

← Back to Features

📋 Overview

WebSocket system provides real-time communication for test progress updates, graph visualization, and live status updates.

Architecture:

  • Main Process: Emits directly via WebSocket
  • Worker Process: Publishes to Redis Pub/Sub → Main Process → WebSocket
  • Socket.IO with typed events
  • Authentication middleware for secure connections
  • Room-based event routing (user rooms, test rooms)

📨 WebSocket Events

authenticated

Sent when client successfully authenticates

Payload: { userId, isAnonymous, timestamp }

test:created

Test was created

Payload: { testId, userId, type, status }

test:started

Test execution started

Payload: { testId, startedAt }

test:progress

Test progress update

Payload: { testId, progress, currentStep, totalSteps }

test:step_completed

Test step completed

Payload: { testId, step, result }

test:graph_update

Graph visualization update

Payload: { testId, graph, nodes, edges }

test:completed

Test execution completed

Payload: { testId, result, duration, summary }

test:failed

Test execution failed

Payload: { testId, error, reason }

test:cancelled

Test was cancelled

Payload: { testId, reason }

test:browser_completed

Browser test completed

Payload: { testId, browser, result }

ai:analysis_started

AI analysis started

Payload: { testId, analysisType }

ai:analysis_progress

AI analysis progress

Payload: { testId, progress, stage }

ai:analysis_completed

AI analysis completed

Payload: { testId, result, insights }

ai:bug_found

AI found a bug

Payload: { testId, bug, severity, location }

chat:message

Chat message update

Payload: { sessionId, message, role }

result:ready

Test result ready

Payload: { testId, result, url }

result:screenshot

Screenshot captured

Payload: { testId, screenshot, url }

result:error

Error occurred

Payload: { testId, error, stack }

system:error

System error

Payload: { error, message, timestamp }

system:maintenance

Maintenance mode

Payload: { message, estimatedDuration }

ping / pong

Heartbeat mechanism

Client sends ping, server responds with pong

🏗️ Architecture

Server: src/websocket/server.ts - Socket.IO server initialization

Service: src/websocket/websocket.service.ts - Singleton service for emitting events

Middleware: src/websocket/middleware.ts - Authentication middleware

Handlers: src/websocket/handlers/ - Connection, subscription, heartbeat handlers

Redis Bridge: src/services/websocket/redis-bridge.service.ts - Redis Pub/Sub bridge

Types: src/websocket/types.ts - Typed events and payloads
