🛣️ API Routing

Request routing, middleware chain, handlers, and validation flow

← Back to Features

📋 Overview

The API routing system handles all incoming HTTP requests, applies middleware in a specific order, routes to appropriate handlers, and manages error responses. It uses Express.js as the core framework with custom middleware for authentication, CORS, logging, and error handling.

Key Components:

  • Middleware Chain: Security, CORS, body parsing, logging, authentication
  • Route Handlers: Organized by feature (auth, chat, tests, etc.)
  • Error Handling: Centralized error handler with proper status codes
  • Validation: Request validation before handler execution

🔧 Middleware Details

1. Security Middleware (Helmet)

  • Purpose: Sets security headers (CSP, CORS policies)
  • Configuration: Relaxed for Swagger UI, strict for other routes
  • File: src/index.ts (lines 38-55)

2. CORS Middleware

  • Purpose: Handles cross-origin requests
  • Configuration:
    • Development: Allow all origins
    • Production: Only allowed origins from ALLOWED_ORIGINS
    • Methods: GET, POST, PUT, DELETE, OPTIONS
    • Headers: Content-Type, Authorization, X-User-ID
  • File: src/index.ts (lines 91-149)

3. Body Parsing

  • express.json: Parses JSON bodies (limit: 10mb)
  • express.urlencoded: Parses URL-encoded bodies (extended: true, limit: 10mb)
  • File: src/index.ts (lines 168-169)

4. Logging (Morgan)

  • Purpose: Logs all HTTP requests
  • Format: Configurable via LOG_FORMAT env variable
  • File: src/index.ts (line 172)

5. Authentication Middleware

  • requireAuth: Validates JWT tokens for protected routes
  • requireDocsAuth: Password protection for documentation
  • File: src/middleware/auth.middleware.ts
