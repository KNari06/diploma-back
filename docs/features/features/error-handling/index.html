⚠️ Error Handling

Error codes, patterns, troubleshooting guide, and error response structure

← Back to Features

📋 Overview

The error handling system provides consistent error responses across all API endpoints. All errors follow a standardized format with error codes, messages, and appropriate HTTP status codes.

Key Features:

  • Standardized Format: All errors return consistent JSON structure
  • Error Codes: Machine-readable error codes for programmatic handling
  • CORS Support: Error responses include CORS headers for allowed origins
  • Logging: All errors are logged with context (URL, method, IP, user agent)
  • Error Types: Custom error classes for different error categories

📊 Error Response Format

All error responses follow this structure:

{
  "success": false,
  "error": "Human-readable error message",
  "code": "ERROR_CODE",
  "details": "Additional details (optional)",
  "timestamp": "2024-01-01T00:00:00.000Z"
}

🔧 Error Classes

1. QAIError (Base Error Class)

  • Properties: message, code, statusCode, details
  • Usage: Base class for all custom errors
  • File: src/types/index.ts

2. ValidationError

  • Extends: QAIError
  • Status Code: 400
  • Code: VALIDATION_ERROR
  • Usage: Request validation failures (Zod, Joi)

3. NotFoundError

  • Extends: QAIError
  • Status Code: 404
  • Code: NOT_FOUND
  • Usage: Resource not found

4. RateLimitError

  • Extends: QAIError
  • Status Code: 429
  • Code: RATE_LIMIT_EXCEEDED
  • Usage: Rate limiting violations

🛠️ Database Error Codes

PostgreSQL error codes are mapped to user-friendly errors:

PostgreSQL Code Error Code Description
23505 VALIDATION_ERROR Unique constraint violation (resource already exists)
23503 VALIDATION_ERROR Foreign key constraint violation (referenced resource not found)
23502 VALIDATION_ERROR Not null constraint violation (required field missing)

🔍 Troubleshooting Guide

Common Issues and Solutions

1. 401 UNAUTHORIZED / INVALID_TOKEN

  • Problem: Token is missing, invalid, or expired
  • Solution:
    • Check Authorization header: Authorization: Bearer <token>
    • Verify token hasn't expired
    • Re-authenticate to get a new token

2. 400 VALIDATION_ERROR

  • Problem: Request body doesn't match expected schema
  • Solution:
    • Check request body structure matches API documentation
    • Verify all required fields are present
    • Check data types match expected types
    • Review details field in error response for specific field errors

3. 503 AI_SERVICE_UNAVAILABLE

  • Problem: OpenAI API is down or rate limited
  • Solution:
    • Check OpenAI API status
    • Verify API key is valid and has credits
    • Wait for rate limit to reset
    • Retry with exponential backoff

4. 503 QUEUE_UNAVAILABLE

  • Problem: Redis connection failed
  • Solution:
    • Check Redis service is running
    • Verify Redis connection configuration
    • Check network connectivity to Redis

5. 502 BAD_GATEWAY

  • Problem: Service is temporarily unavailable (deployment, restart)
  • Solution:
    • Wait a few moments and retry
    • Check service health endpoint: GET /health
    • Verify service is not in shutdown state

6. 500 INTERNAL_ERROR

  • Problem: Unexpected server error
  • Solution:
    • In development: Check error message in response
    • In production: Check server logs
    • Report issue with request details and timestamp
