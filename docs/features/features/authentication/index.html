🔐 Authentication & Authorization

OAuth flow, JWT tokens, session management, and role-based access control

← Back to Features

📋 Overview

Authentication system handles user login, registration, OAuth providers (Google, GitHub, GitLab, Bitbucket), JWT token management, password reset, and session handling.

Key Features:

  • Email/Password authentication
  • Magic Link (passwordless) authentication
  • OAuth providers (Google, GitHub, GitLab, Bitbucket)
  • JWT token refresh mechanism
  • Password reset flow
  • Role-based access control (RBAC)
  • Middleware for protected routes

🌐 API Endpoints

POST /api/v1/auth/signup

Register new user with email and password

Body: { email, password, name? }

POST /api/v1/auth/login

Sign in with email and password

Body: { email, password }

POST /api/v1/auth/magic-link

Send passwordless login link to email

Body: { email, redirectTo? }

GET /api/v1/auth/oauth/:provider

OAuth authentication (google, github, gitlab, bitbucket)

Params: provider

POST /api/v1/auth/logout

Sign out and invalidate session

Headers: Authorization: Bearer {token}

POST /api/v1/auth/refresh

Refresh access token using refresh token

Body: { refresh_token }

GET /api/v1/auth/me

Get current authenticated user

Headers: Authorization: Bearer {token}

POST /api/v1/auth/password/reset-request

Request password reset email

Body: { email, redirectTo? }

POST /api/v1/auth/password/update

Update user password

Headers: Authorization: Bearer {token}

Body: { newPassword }

PUT /api/v1/auth/profile

Update user profile (name)

Headers: Authorization: Bearer {token}

Body: { name }

🛡️ Middleware

requireAuth: Validates JWT token and attaches user to request. Returns 401 if invalid.

optionalAuth: Validates token if present, but doesn't fail if missing.

requireAdmin: Requires user to have admin role. Returns 403 if not admin.

requireCredits(n): Checks if user has enough credits before action.
